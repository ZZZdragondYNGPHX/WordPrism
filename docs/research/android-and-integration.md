# Android 与前后端分层补充调研

调研日期：2026-11-03（America/Los_Angeles）

第一轮已覆盖学习证据、竞品、算法、数据和 LLM，详见[首轮调研](landscape.md)。用户随后确认 Android 手机优先，并明确 Codex 后端、Claude 前端分工。Android 官方能力的补查登记为 [R36–R48](sources.md#r36)；`v0.4` 新增本机调度与拟合候选资料 [R51–R53](sources.md#r51)。

这里记录资料与产品影响。`v0.4` 已确认本地存储、离线学习、手机直连 API 和暂不云同步。Kotlin、Room、WorkManager、具体算法内核及前端框架仍为技术候选；未安装依赖、构建应用或进行真机验证。

## 本地数据与文件

| 主题 | 官方资料支持的判断 | 对本项目的影响 |
| --- | --- | --- |
| 离线数据 | 离线优先应用使用本地持久数据驱动读取；网络变化通过数据层处理：[R36](sources.md#r36) | 本机数据驱动词库、已保存练习、作答、调度与统计；当前要求见[离线能力](../plan/implementation-plan.md#离线能力) |
| SQLite 与 Room | Room 提供 SQLite 抽象、编译时查询检查与数据库迁移支持：[R37](sources.md#r37) | 原生 Android 的持久化候选，仍需实现业务事务、重复识别和恢复验证 |
| 导入与导出 | Storage Access Framework 通过系统文件选择器访问选定文档，返回 URI；创建、选择文档有相应 Intent：[R38](sources.md#r38) | 使用选定文件或流进行导入导出，不要求扫描全部存储；解析层不假设 URI 都有本地路径 |

用户保存到应用私有目录外的备份文件可在卸载后保留，但前提是已经实际导出。系统文件选择器解决文件访问，不自动完成备份一致性或恢复验证。

## 后台生成与中断恢复

WorkManager 适用于需要持久执行的任务，支持约束、状态观察、唯一任务、取消和退避等能力；它不是所有前台即时请求的通用替代，也不承诺精确执行时间。[R39](sources.md#r39)、[R40](sources.md#r40)、[R41](sources.md#r41)

对本项目的推论：

- 当前页面需要的即时生成和长批次导入，应按不同任务特性选择执行方式。
- 输入、任务身份、批次进度和已保存结果进入持久存储，不能仅依赖页面存活。
- 同一逻辑任务避免重复入队；业务提交仍需要幂等保护，唯一任务名称不能替代数据事务。
- 网络条件、省电、系统调度和加急额度会影响执行；前端根据真实状态显示等待、进行、完成或失败。
- 取消时处理后台执行、远程请求及本地保存的竞态；关闭本地请求不保证供应商未完成或未计费。
- 新生成内容晚到时，检查任务与目标内容版本；不能覆盖用户已修改的内容。

生成任务规则维护在 [AI 添加方案](../plan/ai-intake.md#重复操作与失败处理)，每天学习结束后的分析、手动与关闭行为维护在[每日分析方案](../plan/adaptive-learning.md#每日分析与手动控制)。界面通过[任务接口](../plan/frontend-backend-boundary.md#接口能力范围)连接。

## 状态恢复、输入与凭证

| 主题 | 核实内容 | 方案影响 |
| --- | --- | --- |
| 界面状态恢复 | ViewModel 不跨系统进程死亡；保存状态机制适合小型界面状态，不承担全部业务数据：[R43](sources.md#r43) | 页面保存必要 ID 和输入状态，完整作答、进度和任务落库 |
| 触控与无障碍 | Compose 官方资料建议至少 48dp 的触控目标，并通过语义支持辅助技术：[R44](sources.md#r44) | 界面验收包括字体缩放、可达控件和不只依赖颜色的对错反馈 |
| 软键盘 | Android 提供键盘显隐、焦点与窗口调整机制：[R45](sources.md#r45) | 添加词、造句时输入区域和提交动作保持可达；具体实现适配所选 UI 框架 |
| 密钥保护 | Android Keystore 用于保护加密密钥；硬件支持和安全属性取决于设备：[R42](sources.md#r42) | API token 在本机使用受保护的密钥加密保存；不能把 Keystore 描述成 token 永不可提取的保证 |

API 请求已确定由手机直接发出，供应商适配与凭证访问归本机业务核心负责。学习数据导出与凭证管理保持独立，普通备份不包含 API token。

## 前后端可以按模块分离

Android 官方架构建议把数据与业务封装，通过 repository 向界面提供数据；模块化文档说明接口、实现、数据模块与界面模块可以分离，并强调根据项目大小选择模块粒度。[R47](sources.md#r47)、[R48](sources.md#r48)

当前已选择同一 Android 应用内的模块分工：Claude 实现 UI，Codex 提供有类型接口的业务核心和手机 API 适配。首先固定业务能力、数据身份、状态、错误与样例；本地接口绑定随前端框架协调，正式分工由[前后端边界方案](../plan/frontend-backend-boundary.md)维护。

原生 Android 是合理候选，但官方推荐 Compose 不代表已经替用户选定前端框架，也不决定 Claude 的视觉设计。

## FSRS 在 Android 的实现候选

首轮已核查 `ts-fsrs` 的发布元数据、README 和 MIT 许可证：[R07](sources.md#r07)、[R08](sources.md#r08)、[R09](sources.md#r09)。它为算法可复用性提供参考，Android 优先后需要重新匹配运行环境，不能据此默认把 Node 运行时装入应用。

本轮找到 `open-spaced-repetition/FSRS-Kotlin`，已读取 README。它说明实现 FSRS-6，并在 README 声称 MIT；本轮读取根 `LICENSE` 返回 404，完整许可证尚未核实。[R46](sources.md#r46)

该库属于候选，不据 README 的“最新版”措辞判断整个 FSRS 生态的当前版本。正式采用前需要核对算法版本、源码与许可、参考向量、评分行为、时间表示和升级路径。即使采用不同语言实现，原始作答、算法版本和状态迁移仍需可验证。

`v0.4` 已确定调度、历史回放、个人拟合与候选评估均在手机执行，因此还需要验证优化能力，只有调度函数不足以满足需求。本轮继续读取 `fsrs-rs` 默认分支 README、包清单、库入口和根许可证，确认文档及接口包含调度、`compute_parameters`、历史评估与模拟，根许可证为 BSD-3-Clause。[R51](sources.md#r51)、[R52](sources.md#r52)、[R53](sources.md#r53)

当前优先验证这一候选，但尚未实现 JNI 或其他 Android 桥接。默认分支与发布包必须分别核对；算法版本、调度和拟合接口需要来自明确兼容的版本，并在目标 ABI 验证数值、取消和资源消耗。README 的性能描述与平台条件编译不能替代手机实测，完整依赖许可也待采用时检查。

上述资料支持可行的技术方向，具体选择条件统一见[算法内核的选型条件](../plan/implementation-plan.md#算法内核的选型条件)。本轮没有完成 Android 构建或参数训练。

## AI 训练探索的证据边界

用户允许大胆尝试 AI 短文理解、造句与改写。这是明确的产品方向；目前已有研究为间隔练习、检索和部分形似词对照提供依据，但没有验证本项目完整的 AI 生成与评分方案。[R01](sources.md#r01)–[R05](sources.md#r05)

适合先试的设计包括：围绕实际混淆生成新语境、适量输出任务、延迟检查，以及减少重复题面。评估时区分选择、阅读理解与主动表达，避免把开放式 AI 评价直接等同于可靠的记忆评分。

AI 生成能扩展内容，但格式合法、文本不同与内容正确是三件需要分别检查的事。相关训练与验证要求见[手机学习方案](../plan/mobile-learning.md)。

## 本轮结论

- Android 的本地数据、文件访问和持久任务具备可复用机制；最终能力仍需集成验证。
- 本机运行与暂不云同步已确定，前后端按本地接口拆分；语言、框架绑定和依赖版本仍需验证。
- 本机算法候选应覆盖调度和个人拟合，每日分析的触发与参数优化频率分别管理。
- 词库导入、AI 内容补全和当天学习量应分别管理，以支持个人词库和大批资料共同使用。
- AI 练习可以积极纳入早期可用版本，同时保留评分来源、题目版本与可解释的学习记录。

本轮只完成公开资料核查与方案更新。后台实际表现、接口速度、生成费用、内容质量和学习改善幅度尚未实测。
