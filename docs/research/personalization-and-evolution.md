## 通用算法可以作为个性化起点

重新读取了 Anki 官方手册的当前 FSRS 章节，并检查维护方优化器说明。[R06](sources.md#r06)、[R49](sources.md#r49)、[R50](sources.md#r50)

| 资料中的机制 | 可以支持的产品判断 | 适用边界 |
| --- | --- | --- |
| FSRS 优化器从个人复习记录拟合参数 | 复用基础模型也可以学习个人记忆特点，AI 可以主动调度这一能力 | 不能据此保证对本用户已经最优 |
| 目标保持率改变复习频率和工作量 | AI 可以结合个人完成情况、时间目标调整设置 | 目标值是模型控制参数，不是已经测得的真实正确率 |
| 调参和重算到期日期是不同操作 | 参数改变时需要指定生效范围、时间和是否重算未来安排 | 直接重算可能使大量项目集中到期 |
| Health Check 关注数据量和评分习惯 | 个人数据的数量、真实性和评分口径直接影响拟合 | 少量记录或错误评分不能支撑强结论 |
| Simulator 估算不同设置下的工作量 | 可为 AI 提供候选计划的预计负担 | 模拟依赖模型与假设，不是未来实际时长的保证 |
| 优化器使用稳定目标、实际时间、评分及可选时长 | 需要保留能够重建顺序的真实学习事件 | 仅有每日总正确率不足以重新训练完整模型 |

Anki 手册建议使用优化器，避免手工随意修改参数，也不要求高频重复优化。因此本方案让 AI 决定何时拟合、怎样分配训练和是否应用候选，数值参数通过算法定义、个人数据和评估核查。允许提出候选参数属于本项目的实验能力，不是官方资料证明 LLM 能直接写出更好的权重。

检索中发现的旧 `fsrs4anki` 教程已经声明停止更新，后续改用当前 Anki 手册核对。当前手册说明旧的 CMRR 功能已移除，并介绍 Simulator；没有把旧教程中的版本、固定样本门槛或功能名称沿用为本项目要求。

## 数据总览应保留能够解释结果的信息

优化器文档需要每个目标的复习时间序列。用户总览和 AI 分析可以从同一批事实生成，但应保留从汇总指标定位相关明细的能力。

对本项目的设计推论：

- 词数、学习目标数、题数与作答次数分别统计；多词题或多组归属不重复扩大“已学单词”。
- 无提示表现、提示后成功、看完短文后的理解和 AI 写作评价分别记录。
- 混淆次数需要对应的测试机会数；小样本的变化不能只展示百分比。
- 算法预测、真实观察与 AI 解释有不同来源和时间范围，不能混成一个事实分数。
- 保存配置、题目和评分版本，才能判断变化来自学习、题目难度还是策略调整。
- 调整以后继续观察新的数据；历史拟合、工作量模拟和未来实际效果分别报告。

这些是工程与评估设计，不是已经完成的个人实验。正式学习数据尚不存在，本轮也未执行模型训练或 LLM 分析。

## AI 权限与持续调整

用户要求 AI 拥有应用最高权限以实际调整参数。建议通过完整的业务能力目录实现：每项功能声明可调整参数、动作、约束、依赖和回退方式。AI 根据快照选择并调用，后端负责原子生效、版本与真实记录。

这可以覆盖明日学习量、重点目标、训练比例、参数拟合与调度设置。用户明确的 API 选择、推荐词点击加入等要求仍是应用必须遵守的指令；它们不因分析 AI 具有高权限而失效。

为评估变化，建议保存每次配置前后值与依据，并在可能时用按时间划分的数据检查候选。后续实际表现用于继续调整；学习中的进步、题目变化和数据选择会混合影响结果，不能仅凭变化前后对比就宣称因果效果。

## 专属格式与 API 预设的影响

用户已排除跨软件导入导出，因此无需维持第三方字段与历史映射。功能演进的重点转为本软件的容器版本、模块 schema、业务配置和原始事件的兼容性。

专属格式不能自动解决新旧版本差异。未知可选模块可保留，关键结构不兼容则需要迁移或明确停止；只保存未知数据的字节也不保证其跨模块引用仍然有效。正式规则见[专属格式方案](../plan/native-format.md)。

已有官方 API 资料显示，不同协议、供应商与模型在结构化输出和参数支持上存在差异：[R21](sources.md#r21)–[R26](sources.md#r26)。多预设适合按功能选择模型，但需要后端适配、有效参数校验、任务使用版本与分别记录用量。用户界面的布局不会影响这项能力成立，具体规则见 [API 预设方案](../plan/api-presets.md)。
