# 前后端边界与接口方向

版本：`v0.4` · 日期：2026-11-03 · 状态：本机核心与 Compose 前端已接入

用户明确要求：Codex 负责后端，Claude 负责前端。本文维护职责和接口方向；已实现的类型、行为和样例以[本地后端契约](../backend/contract.md)为准，前端门面对应见[映射说明](../frontend/codex-contract-mapping.md)。

## 职责划分

| 范围 | 负责方 | 具体内容 |
| --- | --- | --- |
| 数据与业务 | Codex | 词条、义项、组关系、重复识别、事务、内容版本、学习历史与迁移 |
| 学习引擎 | Codex | 学习目标、题目选择、判分依据、混淆记录、基础调度、参数拟合与策略版本 |
| 学习总览与自动调整 | Codex | 统一统计快照、证据查询、能力目录、AI 分析、变更应用、效果记录与回退 |
| AI 能力 | Codex | API 多预设、功能绑定、适配、归组检索、生成与反馈、任务状态、调用范围和用量 |
| 数据携带 | Codex | 专属容器、版本迁移、预览、依赖与冲突处理、导出及完整恢复 |
| 界面与交互 | Claude | 视觉、组件、布局、导航、展示状态、触控、输入法、无障碍和动效 |
| 前端数据连接 | Claude，遵循契约 | 调用业务接口、展示返回状态、收集用户输入、取消订阅和保持页面状态 |
| 平台接入 | 按边界分工 | 文件选择器与界面授权由前端接入；文件解析、业务存储、持久任务、凭证访问接口由后端提供或约定适配 |
| 联调与交付 | 按职责共同完成 | Codex 验证真实业务与接口，Claude 验证界面完整流程；集成版本在 Android 上验证 |

界面可以独立设计和迭代。判分、归组、调度和写入规则集中由后端维护；界面读取返回的结果及状态，不维护第二套业务事实。

新增能力只向 Claude 约定功能与数据：可查看学习总结和动态计划、结束当日学习、手动分析或关闭自动分析、查看已生效变更并撤销、管理多个 API 预设及功能分配。模块名称、页面位置、图表和控件形式均由前端设计，不由本方案固定。

## 本机运行边界

用户已确认本地存储、离线学习和手机直接调用 API，暂不做云同步。Codex 提供随 Android 应用打包的本地业务核心，前端调用类型化接口；词库、学习记录、调度、统计与任务状态由本机存储和计算维护。

需要模型的操作由手机内的后端适配器读取设备凭证并直接请求用户选定的 API。前端观察统一任务状态，模型响应通过业务校验后保存。参数拟合和候选评估同样在本机完成，执行边界见[本机实施方案](implementation-plan.md)。

Android 官方支持数据模块封装业务、通过接口向界面提供数据：[R47](../research/sources.md#r47)、[R48](../research/sources.md#r48)。原生 Android 可直接消费 Kotlin 接口，其他前端框架通过必要的薄桥接接入；具体绑定与 Claude 的实现方案协调，不复制调度或持久化规则。

当前为进程内 Kotlin SDK：`backend/core-contract` 定义唯一业务类型，`execute / query / observe` 提供命令、查询与修订通知。`android/sdk-contract` 保留为 Claude 的界面门面，`android/sdk-codex` 映射到本地 Maven 构件。应用默认打开 `AndroidWordPrism`；debug 模拟实现不进入 release。视觉与组件沿用 Claude 的实现。

## 接口能力范围

下表使用逻辑操作名表示边界，不是已经存在的 HTTP 路径或最终 SDK 方法。

| 领域 | 候选逻辑操作 | 后端需要返回的关键结果 |
| --- | --- | --- |
| 词库 | `list_words`、`get_group`、`update_word`、`change_membership` | 稳定 ID、义项、关系、版本与实际写入结果 |
| AI 添加 | `submit_intake`、`resolve_intake` | 任务身份、候选归属、实际新增或复用的内容、可撤销操作 |
| 额外词推荐 | `list_recommendations`、`request_recommendations`、`accept_recommendations` | 已有候选、是否需要 API、所用预设、选定后实际结果与撤销身份 |
| 内容生成 | `generate_activity`、`get_activity` | 目标、题型、内容版本、作答条件与题目状态 |
| 学习会话 | `start_session`、`resume_session`、`next_activity` | 会话身份、当前任务、可选操作与已完成进度 |
| 答题与复习 | `submit_answer`、`get_feedback`、`finish_session` | 实际作答记录、反馈依据、是否影响调度及更新后的学习状态 |
| 学习日与计划 | `get_learning_day`、`get_learning_plan`、`finish_learning_day` | 学习日身份、日预算、预计与实际投入、当日完成状态、对应自动分析任务 |
| 开放表达 | `evaluate_response` | 被评价的答案版本、目标词用法、修改建议和评价来源 |
| 学习总览 | `get_learning_overview`、`get_learning_snapshot`、`query_learning_evidence` | 同口径指标、数据截止时间、覆盖范围、观察或预测标识与有关明细 |
| AI 自动调整 | `analyze_learning`、`set_adaptation_policy`、`list_policy_changes` | 所用快照、实际变更前后值、依据、生效时间和可回退状态 |
| 参数能力与评估 | `list_app_capabilities`、`evaluate_policy_candidate`、`apply_policy_change` | 当前可调项、约束、版本、候选评估与真实应用结果 |
| 导入 | `preview_import`、`commit_import` | 专属包用途、模块版本、迁移、依赖、重复和冲突；提交结果与批次身份 |
| 导出与恢复 | `export_data`、`preview_restore`、`restore_backup` | 专属格式中的保留范围、版本兼容性与实际完成状态 |
| 任务与撤销 | `get_operation`、`cancel_operation`、`undo_operation` | 持久状态、可取消或可撤销条件、实际生效结果 |
| API 预设 | `list_api_presets`、`save_api_preset`、`test_connection` | 预设标识、配置版本、可用能力与实际测试结果，不返回完整密钥 |
| 功能分配与调用 | `bind_feature_preset`、`set_call_policy`、`get_usage` | 功能绑定、调用授权范围、额度与按功能和预设统计的真实用量 |

前端能够独立显示词库、题目、生成中的任务、失败后的操作和学习反馈。模型原始文本由后端解析，前端接收适合呈现的结构化内容。

AI 自动调整也使用同一组业务接口、任务状态和撤销体系。后端根据操作发起者与已启用的调用范围执行，不依赖前端隐藏按钮来约束业务行为。参数变更记录通过 `operation_id` 关联通用操作和撤销结果。

结束一个会话与结束当日学习是不同的业务事件。日预算累计、当日完成判定与自动分析名额由后端维护，详细规则见[每日分析与手动控制](adaptive-learning.md#每日分析与手动控制)。

## 契约至少需要说明什么

1. **实体与身份**：词条、义项、组、成员关系、学习目标、题目版本、会话、答案和操作各有稳定 ID。显示名称不承担数据身份。
2. **结果与评分**：结果区分客观答案、用户反馈和 AI 评价；明确具体目标及是否更新调度，规则见[手机学习方案](mobile-learning.md#作答与评分)。
3. **状态与动作**：返回真实状态，以及当前可重试、取消、补充信息或撤销的动作。保存结果和聊天文案分开，状态转换规则在后端维护。
4. **并发与幂等**：明确重复提交、客户端超时、取消、用户修改后的旧结果以及冲突行为；应用内去重不等于供应商不重复计费。
5. **时间**：保存可确定的实际时间点；本地日期和用户时区用于日程展示。变更时区不改写过去的作答时刻。
6. **异常与限制**：给出稳定错误代码、用户可理解的说明及是否适合重试；定义分页、导入批量、文件大小与生成预算的实际限制。
7. **契约版本**：明确字段必选性、默认值和兼容方式；新增题型或状态前同步契约、样例和实现，前端有未知类型的可恢复出口。
8. **平台资源**：导入接口接受平台可提供的 URI 或读取流，普通逻辑不假设 Android 文件一定有传统磁盘路径；凭证通过专门接口访问。
9. **统计与调整**：快照口径、数据范围、配置版本、变更依据和生效时机可对应；详细规则见[学习总览与 AI 调整](adaptive-learning.md)。
10. **预设与调用**：一个任务保留实际使用的预设版本，区分数据读取与需要 API 的动作；规则见 [API 预设](api-presets.md)。
11. **数据演进**：专属容器与各模块 schema 分别版本化，迁移、未知模块与恢复行为遵循[专属格式](native-format.md)。
12. **学习日与预算**：返回累计投入、计划版本、结束原因、自动分析状态与数据覆盖范围；普通暂停不能被解释为当日结束。

具体字段、序列化、错误枚举、文件流与任务观察机制已由[本地后端契约](../backend/contract.md)及同源类型定义。界面展示需要的新派生事实仍由核心提供，不另建一套统计或评分规则。

## 实施时的可独立交付物

Codex 先提供与确认范围一致的本地接口定义、业务库、必要桥接、调用说明和构建方式，以及覆盖实际业务分支的样例数据。样例至少包含成功、空库、歧义、生成中、失败、取消和版本冲突，也覆盖无须调参、调整已生效、撤销后有新作答、预设缺失、离线待执行及旧格式待迁移。

Claude 可以按同一接口和样例完成前端，随后切换到真实实现。样例应由明确的契约约束；模拟结果只说明界面可以呈现该状态，不代表真实 API、算法和数据恢复已经通过验证。

日常接口变化由实现方同步契约与样例。前端提出新的展示需求时，优先补充恰当字段或业务操作，避免直接访问数据库表、解析供应商响应或复制评分逻辑。

本次接入保留 Claude 的页面、组件与视觉，只补齐业务映射、生命周期、恢复和实际状态处理。

## 关键联调场景

这些场景由各实现方完成自己的检查后，在集成版本验证；不额外建立独立评审流程。

- 输入 `linear / liner` 后，界面展示后端实际创建的可学习组；重复提交保持结果一致。
- 以后添加 `linen`，后端更新关系，界面能展示新增差异且原有学习历史保持完整。
- 生成短文或造句任务，提交答案后显示对应版本的反馈；修改答案后旧反馈不会误套到新答案。
- 点击提交后切后台或进程结束，恢复时仍显示正确进度，作答和调度只生效一次。
- 在生成完成附近取消任务，界面按照实际终态展示取消成功或已完成后的撤销入口。
- 导入预览与提交结果可对应；完整备份在空资料库中恢复后，词条、关系和复习记录保持一致。
- 前端统计与 AI 快照使用同一口径；查看总览和已有推荐不发起模型请求。
- 不同功能使用不同预设；任务中途修改预设时，旧任务的来源与结果保持正确。
- AI 自动分析能实际调整明日数量、目标和适用参数，前端显示实际生效记录；撤销仍保留之后完成的学习。
- 导入专属备份恢复预设和 AI 调整历史，未完成任务不会因恢复而自动重新付费执行。
- 断网时已保存的学习流程、统计与调度正常；需联网的操作有真实状态，恢复联网后按规则继续。
- 当日分多次学习时累计预算；完成计划或明确结束学习日后自动分析一次，暂停与重启不重复调用。
- 手动分析与自动任务交错、关闭时请求正在返回等情况下，界面展示与实际生效记录一致。
- AI 在半小时以内的日预算下动态安排词数、题型和时长，提前结束或零新词计划可正常完成。

当前已提供本地接口、运行模块、契约样例、正式包与 Android 安装包。上表场景分别由核心测试、适配器测试、Android 平台测试和实际模拟器流程覆盖；覆盖范围与证据限制见[验证记录](../backend/validation.md)。模型替身不代表真实供应商已通过验证，模拟器也不代表物理手机。早期前端需求保留在[契约需求](../frontend/contract-requirements.md)，现状以[映射说明](../frontend/codex-contract-mapping.md)为准。
