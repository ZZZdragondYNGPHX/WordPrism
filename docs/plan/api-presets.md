# API 预设与功能分配

版本：`v0.4` · 日期：2026-11-03 · 状态：多预设与手机直连已确认，具体协议和接口为方案建议

用户要求保存多个 API 预设，并允许不同功能选择不同预设。本文件定义能力和后端行为；设置入口、展示方式、控件和视觉由 Claude 设计。

## 能力定义

一个 API 预设是可重复使用的一组模型连接与请求配置。用户可以创建、修改、停用、测试预设，并为各项 AI 功能选择预设；多个功能可以共用同一预设，同一服务商也可以保存多个模型或参数组合。

首版由手机内的后端适配器直接调用模型服务，预设与凭证在本机管理。凭证通过受设备密钥保护的存储读取，前端只使用配置和任务接口；本轮尚未验证具体厂商或协议的兼容性。

| 预设信息 | 作用 |
| --- | --- |
| `preset_id`、名称与版本 | 稳定引用与修改记录；改名称不影响功能绑定 |
| 协议适配器、服务商与 `base_url` | 决定请求路径与兼容方式；具体支持范围在技术轮确定 |
| 凭证引用、模型标识 | 凭证通过专门存储取得，模型标识可由用户配置 |
| 支持的请求参数 | 输出长度等通用配置，以及所选适配器实际支持的参数 |
| 能力信息 | 结构化结果、工具调用、上下文限制等已知能力与检测结果 |
| 超时、重试与用量设置 | 用于任务执行、失败处理和自动调用额度 |

预设不等同于固定厂商名单，也不假定一个供应商的所有模型支持同一组参数。能力未知或不匹配时返回明确结果；本地格式检查无需联网，真实连接测试由用户发起，可能产生服务商用量。

## 不同功能选择不同预设

| 功能能力 | 预设用途 |
| --- | --- |
| `word_intake` | 解析自然语言添加、整理词条并匹配已有组 |
| `word_recommendation` | 用户主动要求寻找额外相似词时生成推荐 |
| `explanation` | 重新讲解、补充例句或辨析内容 |
| `practice_generation` | 生成短句、短文理解、造句与改写任务 |
| `writing_feedback` | 评价用户表达、提供目标词用法与改写建议 |
| `learning_analysis` | 读取学习总览、分析个人表现、提出并执行配置变更 |

以上是初始能力标识，前端不必采用相同的页面划分。新功能通过能力目录加入映射，不要求重新设计整套预设机制。

功能优先使用明确绑定的预设；也可选择用户设置的默认预设。没有可用绑定时保持为待配置状态。更换预设不会改写已有内容和学习记录。

一次生成任务可以包含属于同一能力的多个步骤。若用户为不同能力选择不同预设，后端按边界拆分调用；不为了省事静默把全部功能交给一个模型，也不为了增加步骤对相同需求重复请求。

## 调用由用户控制

本节是各功能是否发起 API 请求的统一规则。额外词的具体加入与撤销见 [AI 添加方案](ai-intake.md#额外词推荐与加入)。

| 操作 | 调用规则 |
| --- | --- |
| 查看词库、学习统计、已有题目或已有推荐 | 使用已保存数据，本身不触发新 API 请求 |
| 用户发送 AI 添加、请求新题、点击分析或测试连接 | 该操作发起对应能力的调用，展示实际任务及使用的预设 |
| 从推荐中选择额外词 | 已有内容可复用；如需生成，明确由本次选择触发调用，支持取消与加入后的撤销 |
| 主动寻找更多推荐 | 由用户发起，可以在结果中继续选择；显示推荐不自动连锁补全全部词 |
| 每日自动分析 | 按已启用的每日模式、所选预设和额度执行，支持手动与关闭；详细规则由[每日分析方案](adaptive-learning.md#每日分析与手动控制)维护，不逐次要求批准 |
| 预生成或自动补充训练 | 用户单独启用并设置范围后，按配置、预设和额度执行；不逐次要求批准 |
| 重试或备用预设 | 遵循用户设置的重试及备用路径；没有设置时不静默换到另一个付费预设 |

UI 可以自由组织这些操作，但调用前应能知道是否会发起 API，以及使用哪项功能配置。后端可返回 `requires_api`、解析后的预设和工作量信息；缺乏价格或用量依据时不伪造精确金额。

自动分析 AI 的最高业务权限遵循用户明确的调用选择和额度。它可以在已授权范围内调整生成策略或预设选择；用户明确绑定或锁定的选择保持优先，也不能自行扩大预算来完成自己的方案。

额度可以按请求次数、token 或有可靠价目时的估算费用控制。多个自动任务共用额度时，后端协调预留与结算；供应商的未知用量和取消后的费用仍需保留未知状态，不能承诺严格控制未提供上限的外部账单。

## 任务执行与版本

- 任务开始时记录功能、`preset_id`、预设版本、模型和有效请求参数。任务进行中修改预设，不改变这次请求或把旧结果标成新模型生成。
- 已保存内容和分析保留实际生成来源。重试复用逻辑操作身份，每次尝试分别记录预设与已知用量。
- 运行中的任务、固定绑定和凭证依赖应在停用或删除预设时有明确结果；历史记录仍可解释，不因预设被删除而变成无来源内容。
- 供应商适配器负责参数翻译、响应解析及已知能力差异。业务层接收统一结果，Claude 前端不解析各家原始响应。
- 接口协议或能力不同的模型可以通过相应适配器返回结构化变更；真正执行应用动作的是后端业务接口。
- API 密钥及其他鉴权信息与可分享配置分开。普通查询、学习总览、模型分析输入和专属导出均不包含凭证明文。
- 断网时持久保存已授权任务和输入，联网后检查任务、预设与调用策略再执行；已有内容、统计和本地学习持续可用。
- 用户关闭自动分析后，按[关闭规则](adaptive-learning.md#一次执行手动操作与关闭)取消排队并处理迟到结果；任务保存和参数生效由后端核对当前状态。

## 专属格式中的保存

完整备份保留预设标识、非敏感连接配置、模型配置、功能绑定、调用策略及可保留的历史元数据；凭证需要恢复后重新配置。包含鉴权信息的 header、query 等字段按凭证处理，不能因为是高级配置就混入导出。

恢复时检查预设与当前适配器能力。旧预设仍可作为记录保留，但缺少凭证或不支持的功能保持待配置。自动调用配置可以恢复，未完成任务和自动执行状态按[专属格式恢复规则](native-format.md#导入与恢复行为)重新建立，避免导入文件立即触发付费请求。

## 提供给 Claude 的功能契约

后端应提供预设增改查、停用或删除、连接测试、能力查询、功能绑定、调用策略及按功能和预设查询用量的接口。返回值包含真实状态、可执行动作与稳定错误信息。

前端只需知道：存在多个预设、功能可独立选择、调用受用户控制、有测试和用量状态。具体名称、入口、页面结构和选取方式由 Claude 决定。

当前没有配置真实凭证或发起付费调用，支持的协议、模型与限制在实现时逐项验证。
