# 专属数据格式与版本演进

版本：`v0.4` · 日期：2026-11-03 · 状态：专属格式与本机恢复方向已确认，容器与 schema 为方案建议

用户明确要求导入导出仅限本软件的专属格式，以承载后续不断增减的功能。批量导入仍保留，用于专属数据包；CSV、Excel、Anki 等第三方格式适配从当前范围移除。

首版暂不做云同步，专属备份承担当前的数据携带与换机恢复。设备上可访问的文件支持本地处理，系统文件提供方自身的联网需求单独反映。

## 一个格式承载完整数据

建议使用带清单和版本的容器，扩展名暂为 `.wordprism`，内部采用结构化数据与可选媒体。名称与具体编码在技术轮固定。公开格式说明有助于长期恢复，不要求兼容其他软件的数据模型。

同一专属格式可区分完整备份和选定词库内容两种用途；这属于本软件内的数据范围选择。首版必须完整支持个人资料备份与恢复，内容包需要保留选中内容的全部必要依赖。

| 数据模块 | 完整备份应保留的信息 |
| --- | --- |
| 核心词库 | 词条、义项、组、成员关系、来源、标签、备注与稳定 ID |
| 学习内容 | 差异说明、题目、短文与造句任务、内容版本、答案依据及引用媒体 |
| 学习历史 | 作答、提示、评分来源、目标、会话、学习日与实际时间；被标记异常的记录也保留出处 |
| 记忆与计划 | 算法标识、版本、参数、调度状态、当前计划、质量目标、日预算、预计与实际投入及用户偏好 |
| 学习总览 | 统计口径与分析快照；可重算数据保留相应来源，避免与原始记录冲突 |
| AI 自动调整 | 分析结果、依据快照与覆盖数据、配置前后值、候选评估、已应用及撤销记录、自动执行记录及原始触发日与实际执行日 |
| API 配置 | 非敏感预设、功能绑定、策略及用量记录；不包含凭证 |
| 操作与扩展 | 导入批次、关键变更身份、未来功能的数据模块与依赖 |

仅导出词库内容时，明确排除个人进度、自动调整历史和 API 配置，并为实体引用提供完整依赖闭包。导入它不会获得其他人的“已经掌握”状态。

## 版本与功能增减

专属格式仍需处理本软件不同版本之间的变化。建议至少区分：

- `format_version`：容器和清单的版本。
- `module_schema_version`：各模块数据结构的版本。
- `producer_version`：生成文件的应用版本，供诊断使用。
- `algorithm_version`、`policy_version` 等业务版本：用于解释当时如何生成计划和评分。

清单包含格式标识、文件身份、创建时间、资料库身份、导出用途、模块列表、必需能力、依赖与完整性信息。模块声明使用的 schema 和实际包含的资源。

| 变动情况 | 建议兼容方式 |
| --- | --- |
| 新增可选字段或模块 | 旧版能处理已知部分时，保留未知数据及来源，标为未启用，不静默丢弃 |
| 核心结构发生不兼容变化 | 需要明确的迁移；没有迁移路径时停止写入并说明所需版本 |
| 某功能被停用或移除 | 默认保留其历史模块为归档数据，重新导出时仍可携带；实际清理是用户明确的数据管理操作 |
| 新模块引用旧模块实体 | 记录依赖和稳定 ID，校验引用；仅保存原始未知数据不能保证它与修改后的已知数据仍兼容 |
| 某算法暂不受当前版本支持 | 保留历史与配置，明确当前不能继续解释的状态；不能暗中改用另一算法冒充原状态 |
| 应用从旧版升级 | 在副本或暂存区完成数据迁移与检查，再使新数据生效；保留可恢复的原始版本 |

不能承诺任意新文件都能被旧版完整使用。旧版可以保留的未知内容与无法安全解释的必需模块要区分；格式兼容失败不等于可以丢掉字段后宣称导入成功。

## 导入与恢复行为

1. **识别与检查**：读取清单，确认用途、版本、完整性和依赖，再解析数据。处理文件路径、解包规模、实体数量等限制，不执行包内内容。
2. **预览实际影响**：显示新增、重复、冲突、版本迁移、缺失能力和待配置项。由于格式统一，不提供第三方字段映射流程。
3. **区分追加与恢复**：词库内容包可以批量追加并按 ID 处理重复；完整备份用于恢复对应资料库，不默认与另一份学习历史粗糙拼接。
4. **暂存并验证**：完整恢复在暂存资料库检查实体引用、媒体、算法状态与必要记录，通过后切换为有效数据。失败保留原资料库。
5. **返回真实结果**：记录导入身份、版本迁移和实际变化；重复导入不重复创建同一实体或学习记录。

正在运行的模型请求、系统后台句柄和文件访问授权不作为可移植状态恢复。保留历史任务信息，将未完成任务恢复为待处理；自动调用需在恢复后重新启用，缺少 API 凭证时保持待配置。导入本身不产生新的 API 请求。普通应用重启沿用本机已保存的开关与执行记录，不要求重新启用。

学习日、每日自动执行记录和分析覆盖的数据一并恢复，不能把恢复或切换时区当成新的学习证据。重新启用后按[每日分析规则](adaptive-learning.md#每日分析与手动控制)处理仍有意义的待办，保留已合并和已完成任务，避免重放过期请求。

恢复后的统计可从原始事件按对应口径重算。过去生成的 AI 分析仍保留其原快照与截止时间，不能用今天重算的总览替换其当时依据。

明日计划、时区与到期时间的展示按当前有效配置计算，历史作答的实际时刻不被改写。算法参数变更或撤销后的恢复规则遵循[自动调整方案](adaptive-learning.md#生效时间与撤销)。

Android 端通过系统文件选择器读写选定文件，后端处理容器、迁移与恢复。前端展示范围、进度和结果，布局由 Claude 设计。

## 实现后的验证

- 空资料库恢复完整备份后，词条、关系、内容、实际作答、学习日、预算、算法状态、AI 调整历史和 API 绑定可核对。
- 同一个数据包重复导入，实体和历史数量保持一致。
- 新增字段、未知可选模块、移除功能与不兼容必需模块各有明确结果，重新导出不无声丢失可保留信息。
- 无效引用、损坏资源、部分写入或进程中断不会使当前资料库进入半恢复状态。
- 带有新作答的资料恢复或撤销策略时，真实学习进度被保留。
- 导出不包含凭证，恢复不会自动重新发送生成请求或开启付费自动任务。

本轮未生成真实格式样本或执行迁移测试；正式 schema、兼容矩阵与参考样本会随技术方案固定。
