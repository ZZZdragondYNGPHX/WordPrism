# 手机学习与 AI 训练

版本：`v0.4` · 日期：2026-11-03 · 状态：混合训练、本地离线、质量优先与日预算已确认，具体机制仍为方案

对应方向见[方案索引](index.md)。本文维护学习行为、题型和评分规则；页面布局、视觉风格、组件与交互实现由 Claude 负责，工程边界见[前后端方案](frontend-backend-boundary.md)。

## 学习目标

以个人易混词库为基础，让用户在不同时间、不同语境下认清并用对单词。背词是主任务，阅读理解和写作使用同一套词条、义项与混淆关系，训练结果也回到这套记录中。

每天大致投入半小时以内，以记忆质量为先。计划根据实际表现动态安排，允许减少新学、加强必要回忆或提前结束；一天多次学习累计预算。具体计时、质量依据与预算行为统一见[个人目标与动态预算](adaptive-learning.md#个人目标与动态预算)。

成熟的复习算法、数据持久化与导入恢复机制优先复用。基础调度可根据个人数据拟合参数，并由 AI 结合学习表现持续调整计划、训练组合和设置，规则见[自动调整方案](adaptive-learning.md)。当前研究支持间隔练习与主动检索，但尚无证据证明本项目的 AI 题型组合一定更有效，依据见[学习研究](../research/landscape.md#学习证据及产品影响)。

## 一次手机学习

以下是功能顺序建议，不限定页面数量或导航样式。

1. **开始或继续**：得到当前有效策略安排的到期任务、新学量和预计时间，结合当日已投入时间继续上次中断的任务。初始优先处理必要复习；用户设置或已启用的 AI 调整可以改变数量和优先级，策略版本保持可查。
2. **判断基础**：对新词提供“还不认识”和“认识但容易混”的路径。前者先学习基本义，后者直接辨析。已有历史可辅助选择，用户可以改选。
3. **理解差异**：显示简短义项、关键字母或搭配差别及例句；可以补充个人笔记。
4. **独立作答**：隐藏刚才的差异高亮与解释，用明确的题目检测目标能力。根据训练强度安排选择、无选项回忆、短文或造句。
5. **得到反馈**：客观题及时给出答案依据；错选时针对实际混淆词解释。开放表达保留原答案，提供可追溯的 AI 反馈和修改机会。
6. **继续、暂停或结束当天**：已经完成的作答立即保存，未完成任务保持可恢复状态。完成一个小节或暂停只结束当前会话；当日计划完成或用户明确结束当天学习时，记录学习日结束事件。
7. **查看总结与调整**：后端更新使用统计，用户可浏览；每日自动分析依据学习日结束事件运行，手动与关闭也可用。触发、去重和离线延迟统一见[每日分析与手动控制](adaptive-learning.md#每日分析与手动控制)，实际变化可查看和撤销。

专属数据包批量导入后的词先进入词库，何时开始学习由计划决定。导入一千个词不等于当天安排一千个学习项目。只有必要的基础学习和实际辨析目标进入调度，不为每组展开所有词对与题型组合。

孤立单词也能进行基础学习；以后发现混淆关系时再归组，不要求先构造一个组才能使用。

## 训练方式

| 方式 | 学习任务 | 针对的能力 | 本轮建议 |
| --- | --- | --- | --- |
| 词形与词义辨认 | 根据明确义项选出正确单词，变化选项顺序 | 认识词、分清字母结构 | 作为快速基础训练 |
| 短句选词与替换判断 | 依据句法、搭配或语境选词，判断是否能替换 | 辨析用法和具体义项 | 常用主任务，保留多个合理答案 |
| 无选项回忆与拼写 | 根据含义或有充分约束的句子回忆词 | 主动提取词形与词义 | 少量穿插，强度可调 |
| AI 短文理解 | 阅读围绕目标词生成的短文，解释含义、选择合理推断或判断替换 | 新语境下的理解与辨析 | 首个可试用版本纳入 |
| AI 造句 | 按给定意图用一个目标词造句，或选合适词后造句 | 主动用词与搭配 | 首个可试用版本纳入 |
| AI 改写与纠错 | 修正用错的词，或把一句话改写到另一个词适用的语境 | 比较用法、迁移表达 | 与造句共用反馈能力，作为早期实验 |

用户已选择混合训练：快速辨析维持手机使用的连贯性，穿插短文、回忆和单句输出。具体占比由质量目标和个人表现调整，不预设所有词都要完成全部题型。需要更多理解或表达时间时，可以减少任务数量；AI 可改变训练组合，生效与回退遵循[自动调整方案](adaptive-learning.md#生效时间与撤销)。

## AI 训练与内容变化

### 围绕真实混淆生成

后端根据目标义项、组内差异、实际错误、已见题目和可用基础，生成适当的任务。对 `linear / liner`，可先训练词形与词性，再换一个新句子或短文检查是否仍分得清；以后加入 `linen`，增加与新成员有关的训练。

短文只需要自然呈现部分目标词，不强迫把一组的所有成员塞进同一段话。生成约束包括目标义项、背景词难度、长度、主题、需要检测的能力和已见内容；初期可尝试数句到一小段，长度根据试用调整。

短文理解的问题应真正依赖语境，可涉及指代、意图、合理替换或具体词义。仅靠找到原词即可作答的题，不据此证明用户能主动回忆该词。造句可提供中文意图或情境，让用户选择合适词完成一句表达。

### 减少固定答案依赖

- 变化句子、语境、提问方式和选项位置；识别题与回忆、输出题交替使用。
- 保留内容版本和近期题目记录，避免只是换标点、名字或选项顺序就称作全新训练。
- 新题检测同一稳定的学习目标，不因每次换句子而重建一份记忆状态。
- 调整词义、语法难度或信息量时记录条件，避免把题目变难造成的错误全部解释为遗忘。
- 讲解和练习分开，记录提示、答案曝光和刚看过相关材料的情况。
- 定期观察延迟后、未见语境下的表现；同一道题的短期重复成功仅代表这次条件下的表现。

这些变化旨在减少对题面、答案位置和固定操作的依赖，不能保证完全消除机械记忆。

### 生成与反馈的等待

学习分析可按实际情况补充题库，调用与锁定规则见[API 方案](api-presets.md#调用由用户控制)。已经保存的内容随时可用；没有新题时可使用已存题目、切换训练或稍后继续。生成进度只显示真实可知的状态。

开放造句需要等待 AI 时，原答案先保存。用户可以继续其他任务，之后查看反馈；反馈必须对应当时的答案版本。修改答案后，旧反馈仍有历史价值，但不能覆盖新答案的评价。

离线学习使用本机词库、已存题目和本地调度。新的 AI 生成与开放表达反馈保留待处理状态，联网后按调用规则继续；无法客观判定的答案不因断网而自动计分。能力范围见[离线能力](implementation-plan.md#离线能力)。

请求次数和输出规模按用户设置控制。重复题复用已有材料；不会因为用户返回页面就自动重新请求模型。批量生成与取消规则统一见 [AI 添加方案](ai-intake.md#重复操作与失败处理)。

## 作答与评分

| 观察到的行为 | 记录与反馈 | 对记忆调度的影响建议 |
| --- | --- | --- |
| 无提示完成可判定题 | 保存目标、答案、题目版本和结果 | 按固定评分映射更新对应学习目标 |
| 选错或明确表示忘记 | 保存实际选项及目标，形成可观察的混淆方向 | 对被测目标记失败；选项中的其他词不自动判错 |
| 答对但觉得困难 | 保存正确结果与用户反馈 | 保持为成功；可映射到困难档 |
| 用过提示、看过答案再答对 | 标记提示和曝光条件，给出练习反馈 | 不按无提示成功处理；映射在技术轮固定 |
| 短文中看见目标词后理解正确 | 记录阅读语境下的理解表现 | 只影响适用的理解目标，不推导出自由拼写或无提示回忆能力 |
| 自由造句或改写得到 AI 评价 | 分开记录目标义项、用词、搭配与其他语法意见，引用原答案片段 | 首版作为辅助反馈；不把模型整体分数直接写成 FSRS 成功或失败 |
| 题目有多个合理答案或被标记有问题 | 接受已定义的合法答案；有争议的题进入待修正状态 | 暂停有争议结果对正常统计和调度的影响，按纠正规则处理 |
| 用户跳过、退出或任务中断 | 保存会话状态与跳过原因（若有） | 不据此制造一次遗忘记录 |

无选项任务需要提前定义允许的词形和答案范围，不能对所有输入都使用严格字符串相等。开放表达不要求用户复现一条标准句；AI 反馈区分“用错了”“可以但不自然”“同样合理”。与目标词无关的小错误，不直接判定该词已经遗忘。

一次题目可涉及多个词，但必须明确实际测试了哪些目标。一篇短文的多个相关问题不自动生成多次相互独立的复习成功；如何聚合作答，在后端评分规则中统一实现。

基础调度器负责产生一致的记忆状态与时间安排；内容选择、评分和调度配置使用有版本的策略。AI 可通过统一能力调整适用的设置，详细边界见[算法微调方案](adaptive-learning.md#算法微调的执行方式)。学习历史保留当时的答案、评分依据和算法版本；后续参数调整不改写这些事实。

## 触控输入与中断恢复

这些是双方实现时的功能要求，具体呈现由 Claude 设计。

- 点击、提交和保存有明确反馈；只有收到持久化结果才显示“已保存”。允许键盘和输入法正常编辑，不把中文输入法的确认直接误当作交卷。
- 多次点提交只产生一份有效作答；返回、转屏、切后台和重建页面不重复计分。
- 作答提交、复习记录和调度状态作为一致的业务操作保存。未提交的答案草稿与已提交作答分别存储。
- 完成一道题后立即允许继续，反馈动画不锁住高频操作；减少动态效果设置下仍能理解状态。
- 触控目标、字体缩放、屏幕阅读、键盘遮挡和仅用颜色提示等问题须在实际 Android 界面验证。官方资料建议至少 48dp 的触控目标：[R44](../research/sources.md#r44)。
- 会话 ID、答案草稿和生成任务应能在进程被系统结束后恢复；仅保存在 ViewModel 的状态不满足这一要求：[R43](../research/sources.md#r43)。
- 撤销、取消和迟到结果的业务状态以[任务规则](ai-intake.md#重复操作与失败处理)为准，前端展示真实保存结果。

## 探索与验收

| 要验证的假设 | 应观察的证据 |
| --- | --- |
| 换语境有助于分清词 | 延迟后、未见题目中的正确率及实际混淆方向 |
| AI 短文和造句适合日常手机学习 | 完成时间、退出位置、用户愿意继续的比例，以及新语境表现 |
| 输出训练有额外价值 | 无选项回忆与用词表现，和单纯辨认表现分开比较 |
| 自动生成减少整理负担 | 从输入到可用内容的时间、修改比例和归组纠正次数 |
| 内容质量足以支持训练 | 释义和语境正确性、多个合理答案、反馈误判及用户纠错 |
| 变化题目在成本上可持续 | 真实 token 用量、生成等待、缓存复用、实际练习量 |
| AI 调整适合个人表现 | 配置变化前后的目标表现、实际负担和回退情况；使用一致的统计口径 |

个人试用可用来调整方向；样本少、题目难度不同或没有控制条件时，不宣称已证明因果效果。改动训练策略应记录版本，使效果变化有迹可查。

当前尚无可评分的界面或真实服务调用。本轮的交互检查只形成实现要求，实际可用性、流畅度、内容质量和学习效果待实现后验证。
